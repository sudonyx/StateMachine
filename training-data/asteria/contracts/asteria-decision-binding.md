# Asteria decision binding semantics

This document describes only fields and checks present in the Decision API
implementation. It is not a State Machine binding protocol.

## Assessment fields

| Concept | API representation | What the Decision API verifies |
|---|---|---|
| Release identity | Request `releaseId`; response `binding.releaseId`; also a fact-snapshot entry named `releaseId` | Requires a non-blank string and inserts that value into the fact snapshot. It does not resolve or authenticate a release record. |
| Assessment generation | Request `assessmentGeneration`; response binding; fact-snapshot entry | Requires an integer of at least 1 and inserts it into the fact snapshot. It does not compare the generation with an external workflow or release history. |
| Material digest | Request `materialDigest`; response binding; fact-snapshot entry | Requires a non-blank string and includes that exact string in the fact snapshot. The digest format, referenced material and digest-to-material correspondence are not checked. |
| Workflow instance identity | Not exposed | No workflow/instance identifier is accepted, generated, selected, or returned. |
| Expected operation identity | Not exposed | No operation identifier is accepted, checked, or returned. |
| Parent revision | Not exposed | No parent revision or predecessor is accepted, checked, or returned. |
| Selected policy-version identities | Response `selectedPolicySourceVersions`; evidence `ruleSources` | Loaded from the registered policy-version repository and selected using the requested temporal context. Replay verifies the registered identity and source/rule digests against the stored evidence. A no-version result has an empty list. |
| Fact-set digest | Response `factDigest`; evidence `factSet.digest` and `factSet.digestAlgorithm` | Computed by the Decision API from its canonical fact snapshot using SHA-256. It covers the API's declared Asteria facts, including the three explicit binding facts and represented Missing/Unknown/Unavailable states. It is not a digest supplied by the caller. |
| Persisted evaluation ID | Response `evaluationId`; evidence `evaluationId`; replay path parameter | Generated by the engine and persisted when an applicable version is selected and evaluation completes. It is null when no policy version is selected; that unresolved response is not persisted and cannot be replayed. |
| Original evaluation evidence | Response `evidence` | The evidence object is built by the Decision API and stored with the evaluation. It includes the fact snapshot, selected policy source/rule evidence, rule results, composition and generic decision evidence. Replay reproduces evidence from the stored snapshot and exact registered version. |

## Caller-supplied versus API-verified values

`releaseId`, `assessmentGeneration`, and `materialDigest` are caller-supplied
binding values. The API checks only non-blank release/digest strings and a
positive generation. It copies them into `binding` and into the evaluator's
fact snapshot; they are not independently cross-checked against State Machine
records, a release artifact, a workflow, or a trusted digest authority.

The API does independently load registered AST-POL-001 metadata, apply
business-effective and known-at temporal selection, calculate the fact-set
digest from the normalized fact snapshot, create the evaluation identifier,
and preserve the evidence. This does not establish that caller-provided
business facts or binding values are true, authorized, fresh, or tied to the
same external release operation.

The selected version identity returned by an assessment is API-selected
repository metadata, rather than a version identity supplied in the request.
The separate `GET /asteria/releases/policy-versions` response lists registered
version metadata. No Asteria route returns source-document or executable-rule
contents for policy-source inspection.

## Cross-system integration gaps

Safe operation-level binding is not currently available because the contract
has no workflow instance identity, expected operation identity, or parent
revision. The material digest is echoed but is not validated against material.
The release identity and assessment generation are not checked against an
external system. A State Machine integration must not treat these echoed
values as independently authenticated binding evidence.

The `evidence` member is null when no version is selected. For a persisted
assessment, it is the original saved generic decision evidence; the Asteria
projection additionally reports outcomes and obligations. Neither outcome nor
obligation means that a check or approval was performed. `deploymentAuthorised`
is always false.
