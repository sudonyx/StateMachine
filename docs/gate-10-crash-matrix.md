# Gate 10 crash and recovery matrix

The test-only interruption controls are mapped only in Development when `DURABLE_STATE_MACHINE_ENABLE_TEST_CONTROLS=true`. Exception injection is not equivalent to operating-system process termination. “Host-restart verified” refers to disposing and recreating the API test host against the same SQLite file, in one test process. Child-process tests terminate only their owned API process at the boundaries shown below, then start a fresh process against the same disposable SQLite file.

| # | Interruption point | Durable boundary and expected recovery | Verification status |
|---|---|---|---|
| 1 | Before intake commit | The request is not recoverable until the first SQLite transaction commits. | **Deterministic fault-injection verified**: no inbound receipt remains. |
| 2 | After intake commit, before evaluation | Canonical envelope, digest, identity, original revision, definition binding and authority classification remain in `InboundMessages` as `Received`. A receipt-specific resume reuses that data. | **Operating-system process-kill verified** and **deterministic fault-injection verified**: the child API process is terminated at this boundary; a new process resumes once with one accepted history row. |
| 3 | During guard evaluation | The guard is pure. Its transaction rolls back, leaving intake `Received`; continuation re-evaluates using stored facts/evidence and no external decision fetch. | **Deterministic fault-injection verified**; recovery after this exact interruption is tested in the same restarted test host. No new Meridian request is made by the recovery path. |
| 4 | External work pending | Effect intent and expected operation remain durable before provider dispatch. Recovery reads local status without submitting a replacement. | **Operating-system process-kill verified** at the committed-intent/before-provider boundary: a fresh process reports pending external work and the provider was not called. |
| 5 | External result observed before local acceptance | Provider/harness outcome and workflow observation acceptance are separate boundaries. A local observation can only proceed through Gate 5 authority, operation/source/revision/lifecycle checks. A result body held only in process memory is unavailable after process loss. | **Partially verified** by existing Gate 6/7 exception-injected boundaries. No new durable provider-response staging or process-kill test. |
| 6 | During final transition/projection persistence | The receipt final status, attempt/evidence, accepted state/revision/history, timers, effects and expected-operation resolution commit in one SQLite immediate transaction. A child API is also killed at the pre-final-save pause; restart observes the prior projection and `Received` intake. Existing projection-corruption replay remains read-only and detects mismatch without repair. | **Operating-system process-kill verified** immediately before final persistence; **deterministic fault-injection verified** at finalization/projection-save boundaries; existing SQLite trigger tests exercise a write failure. No kill during an individual SQL statement. |

## Cross-cutting verification and limitations

- A replay/recovery integration test injects a counting HTTP handler for the Generic Harness client and asserts zero calls while running reconstruction, decision verification and repeated recovery assessment. It also compares instance, attempts, receipts, expected operations, timers, effects and transition history before and after.
- Existing SQLite immediate transactions, conditional revision updates and unique accepted-history revision constraints remain the cross-host arbitration mechanism. A new two-host same-intake resume race verifies one accepted history row. Recovery versus an unrelated normal command, cancellation and timer expiry are not each independently fault/barrier tested here.
- Process termination is verified after intake commit/before evaluation, after effect-intent commit/before provider dispatch, and immediately before final local persistence. It is not verified after an external result or during an individual SQL statement.
- No Gate 10 test persists an external response body between provider completion and observation acceptance. Unknown or merely in-memory outcomes remain unresolved; recovery does not invent a response from harness execution status.
- No historical intake is synthesized for pre-Gate-10 records. Older attempts lacking Gate 4 evidence remain state-reconstructable but not decision-verifiable.
