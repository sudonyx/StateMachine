# Gate 6 crash matrix

All fault-boundary cases below are reproducible using the development-only one-shot controls and SQLite-backed integration tests in `Gate6EffectTests`. They model an interruption by throwing at a named boundary; they are not evidence of operating-system process termination. Scenario 2 additionally disposes one `WebApplicationFactory` API host and starts another against the same SQLite files. No test kills a real process.

## Interpretation

- **Durable intent** proves that the workflow requested an effect, not that a provider received or completed it.
- **Provider-side success** proves only what the synthetic provider persisted. It does not prove the local workflow saved the response or accepted an observation.
- **Local result persistence** proves that the API recorded a provider response; it is still distinct from Gate 5 observation eligibility.
- **Accepted observation** proves the declared input passed Gate 5 checks and the generic evaluator accepted its mapped event.
- **Completed workflow transition** is recorded only by the evaluator's accepted transition transaction.

An unresolved outcome remains unresolved until sufficient provider evidence or a provider-guaranteed same-identity recovery establishes a result. A timeout, missing response, or absent provider row is not automatically a confirmed failure.
